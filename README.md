# Vernoxy Pulse

Enterprise Sales CRM + HRMS monorepo built with NestJS, React + Vite + TypeScript, Prisma (by introspection), plain-SQL dbmate migrations, and clean architecture enforced by dependency-cruiser.

---

## Hard Rules

1. **Schema Changes via Plain-SQL Migrations Only**:
   - New database schema changes are added exclusively via a **NEW** dbmate migration after existing ones.
   - Never edit an applied migration.
   - Never run `prisma migrate` or `prisma db push`. `schema.prisma` stays generated by introspection (`pnpm db:pull` followed by `pnpm db:generate`).
2. **Environment & Branch Safety**:
   - Automated tests run on local PostgreSQL + Mailpit.
   - Manual runs may use the Neon DEV branch (`br-late-silence-b51ydwko`).
   - NEVER touch the production database or branch.
3. **Secrets Hygiene**:
   - Never log, print, or commit secrets: passwords, hashes, OTP codes, tokens, refresh cookies, private keys, connection strings.
   - OTP codes exist only inside the email body and are redacted in all logs.
4. **Clean Architecture Enforced**:
   - Domain pure; application depends on domain and ports; infrastructure implements ports; presentation calls application.
   - `pnpm arch:check` must pass with zero violations. No business logic in controllers.
5. **No Hard Deletes & Append-Only Guarantees**:
   - Hard `DELETE` and `TRUNCATE` operations are rejected by database triggers. Soft delete via `deleted_at` and `deleted_by`.
   - `auth_events` table is append-only, partitioned by month with a catch-all default partition.
6. **Reporting Rule**:
   - All automated test outputs and verification runs must save raw output directly to `logs/` and never retype or fabricate results.

## Architecture Overview

```
apps/api/src/
├── core/                        # Global filters, logging, Prisma service, Zod env config
└── modules/auth/
    ├── domain/                  # Pure TypeScript domain rules (zero external dependencies)
    │   ├── data/                # Top common passwords blacklist
    │   ├── models/              # Pure domain models (User, Session, OtpChallenge)
    │   └── services/            # Pure policies: lockout, OTP generation/HMAC-SHA256, password, refresh rotation
    ├── application/             # Application use cases & ports
    │   ├── ports/               # Ports: EmployeeAuthRepository, SessionRepository, OtpRepository,
    │   │                        #        AuthEventRepository, PasswordHasher, TokenService, OtpCodeService, MailPort, Clock
    │   ├── services/            # AuthService (login, verify, resend, refresh, logout, password reset/change)
    │   └── errors/              # Framework-independent application exceptions
    ├── infrastructure/          # Adapters implementing application ports
    │   ├── clock/               # SystemClock
    │   ├── mail/                # SmtpMailAdapter (nodemailer), InMemoryMailAdapter (test-only)
    │   ├── persistence/         # Prisma/raw-SQL repositories
    │   └── security/            # Argon2PasswordHasher, HmacOtpService, JoseTokenService (RS256, JWKS)
    └── presentation/            # HTTP entry points (NestJS controllers, guards, DTOs)
        ├── controllers/         # AuthController (10 endpoints), JwksController (/.well-known/jwks.json)
        ├── dto/                 # Class-validator DTOs with Swagger API decorators
        └── guards/              # JwtAuthGuard (validates active session, active employee, must_change_password)
```

## Authentication Endpoints

Base path: `/api/v1` (except `/.well-known/jwks.json`)  
Error format: RFC 7807 `application/problem+json`

| Method | Endpoint | Auth | Throttling | Description |
|---|---|---|---|---|
| `POST` | `/api/v1/auth/login` | Public | 10 / min | Initiates 2FA login with email & password; sends 6-digit OTP |
| `POST` | `/api/v1/auth/login/verify` | Public | 10 / min | Verifies OTP code; returns access JWT & sets `pulse_rt` cookie |
| `POST` | `/api/v1/auth/login/resend` | Public | 3 / min | Resends OTP obeying 60s cooldown and 5/hr cap |
| `POST` | `/api/v1/auth/refresh` | Cookie (`pulse_rt`) | 100 / min | Rotates refresh token cookie; requires `X-Requested-With: pulse-web` |
| `POST` | `/api/v1/auth/logout` | Cookie or Bearer | 100 / min | Revokes current session with reason `logout`; clears cookie |
| `POST` | `/api/v1/auth/logout-all` | Bearer | 100 / min | Revokes all sessions of the employee (`logout_all`) |
| `GET` | `/api/v1/auth/me` | Bearer | 100 / min | Returns current employee profile, role, department |
| `POST` | `/api/v1/auth/password/change`| Bearer | 100 / min | Changes password; revokes all OTHER sessions; clears `must_change_password` |
| `POST` | `/api/v1/auth/password/forgot`| Public | 3 / min | Always returns generic 202 Accepted; sends reset OTP if valid |
| `POST` | `/api/v1/auth/password/reset` | Public | 5 / min | Verifies reset code; updates password; revokes all sessions |
| `GET` | `/.well-known/jwks.json` | Public | 100 / min | RSA public keys in standard JWKS format with `kid` |

## How to Run Locally

### 1. Prerequisites & Services
Ensure Docker (or local PostgreSQL and Mailpit) is running:
```bash
docker compose up -d postgres mailpit
```

### 2. Generate Authentication Secrets (Safe & Idempotent)
Generates RSA keypair, Key ID, and OTP HMAC secret and appends them to `.env` only if missing (never prints secrets):
```bash
pnpm auth:gen-secrets
```

### 3. Run Database Migrations
```bash
pnpm db:migrate
```

### 4. Bootstrap Initial Admin User
Interactive CLI with hidden password prompt:
```bash
pnpm bootstrap:admin
```

### 5. Start Development Servers
Start both backend API (`http://localhost:3000`) and frontend Web (`http://localhost:5173`):
```bash
pnpm dev
```

## Verification & Manual Testing Steps

1. **Verify Mailpit UI**:
   - Open browser at `http://localhost:8025` to inspect sent emails.
2. **Interactive Web Login**:
   - Navigate to `http://localhost:5173/login`.
   - Log in with the admin credentials created during bootstrap.
   - Retrieve the 6-digit verification code from Mailpit (`http://localhost:8025`).
   - Enter code on `/login/verify` and confirm redirection to `/` dashboard.
3. **Token Refresh on Reload**:
   - Refresh the browser on `/`. Confirm the session is automatically restored via `/api/v1/auth/refresh`.
4. **Multi-Tab Logout Sync**:
   - Open two tabs to `http://localhost:5173/`. Click "Log out" on Tab 1. Confirm Tab 2 immediately redirects to `/login`.
5. **Run Full Test Suites**:
   - SQL tests: `pnpm db:test` (113 assertions pass)
   - Architecture check: `pnpm arch:check` (0 violations)
   - API E2E tests: `pnpm --filter @vernoxy-pulse/api test:e2e` (23 tests pass)
   - Playwright Web E2E: `pnpm --filter @vernoxy-pulse/web test:e2e` (8 tests pass)
   - Full monorepo verification: `pnpm db:verify-fresh && pnpm build && pnpm test`
